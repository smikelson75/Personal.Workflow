## Problem
- Workflow runs Stall often enough to defeat the purpose of the workflow.
- Products can pass every gate and still break their spec, so results cannot be trusted. Both pains weigh equally.
- Desired outcome: runs reach done with no hand fixes, and done means every spec rule is tested wherever it applies.

## Users
- `Developer` - drives brain-storm, behavior-spec, and `/pull-work` on personal projects; wants runs to finish without hand fixes.
- `Skills/agents` - run each stage; need each stage's output to fit the next stage's inputs.

## Workflow
- trigger: the Developer runs brain-storm, then behavior-spec, then `/pull-work` until done.
- each stage commits its own output, so the next stage starts from a clean working tree.
- planned stops are Checkpoints; each is one bundled question.
- alternate path: the spec changes after a plan exists -> `/pull-work` routes to planning, even when the plan is done.
- alternate path: the Developer finds a defect in built work -> `/pull-work bug: <description>` -> planning adds fix work.
- failure path: no mutation Language Add-on installed -> mutation recorded unsupported; the run continues.
- successful outcome: the plan reaches done with Checkpoints as the only stops.
