## Existing Solution
- Every Workflow Core agent pins its model and effort in Copilot's format: a ranked `model` list of Copilot display names and a `reasoning-effort` value.
- The Update Script copies agent files unchanged into the Home Repo's `.claude/agents/`, which both Harnesses read.
- Claude Code does not understand Copilot's pin format, so Workflow Core agents there inherit the main session's model and effort.
- In the copy layout, Claude Code finds no Workflow Core agents at all.

## Problem
- Without pins, an agent's model and effort are set by the main session, not by the job the agent was designed for, which wastes usage and quality.
- Desired outcome: unchanged from `context-2026-11-25-1955.md`; in either Harness, each agent runs at the model and effort suited to its job, with one place to edit.

## Workflow
- edit: the Developer changes an agent's `model` list or `reasoning-effort` in `Personal.Workflow`.
- update: the Update Script installs agents into the Home Repo and names any agent that fell back to a default.
- run: Copilot CLI uses the list as written; Claude Code uses the first Claude model in the list.
- fallback: no Claude model in the list, or no effort -> shipped default, named in Update Script output.
- successful outcome: one edit and one Update Script run change an agent in both Harnesses.

## Requirements
- R48 - In the Home layout, Claude Code runs each Workflow Core agent on the first Claude model in its `model` list at its `reasoning-effort` (nearest supported), not the session's model. Accept: with the session on Opus, Claude Code runs `repo-scout` on Haiku at `low` and `planner` on Opus at `high`.
- R49 - Copilot CLI's agent pins stay exactly as written in each agent file, in both layouts, with no added pin fields or sync step. Accept: Copilot in `Personal.Workflow` and in the Home Repo runs each agent on its first available listed model at its effort, as before.
- R50 - When an agent's `model` list has no Claude model or it has no `reasoning-effort`, Claude Code uses the shipped default, and Update Script output names each such agent and default. Accept: with Claude entries removed from `coder`, an Update Script run prints a line naming `coder` and the default model, and Claude Code runs `coder` on it.
- R51 - One edit to an agent's `model` list or `reasoning-effort` in `Personal.Workflow` plus one Update Script run changes that agent in both Harnesses as the list dictates. Accept: changing `coder`'s Claude entry from Haiku to Sonnet changes its Claude Code model with no other file edited, and putting Gemini Neon first changes only Copilot.

## Scope Guardrails
- in: R48-R51.
- out: pins for Claude Code in the copy layout; proof of which model an agent actually ran on (both Harnesses display it).

## Constraints
- Rule to remember: the Claude model listed in an agent's `model` list is what Claude Code runs, wherever it sits in the list.
- Workflow Core agents use `reasoning-effort` levels `low`, `medium`, `high`.
- imposed format: agent-file fields and model names per Harness - owner: Anthropic and GitHub.
- accepted risk: whether Claude Code honors a per-agent effort is unverified; if not, R48's effort half is reported as a limitation.

## Success
- v1 succeeds when R48-R51 hold: Claude Code agents run at their designed model and effort, Copilot is unchanged, and pins are edited in one place.

## Decisions
- rejected: same exact model in both Harnesses - drops Copilot's non-Claude fallbacks and breaks when a model is unavailable.
- rejected: separate hand-written pins per Harness - two values per agent drift.
- rejected: a shipped tier mapping with workflow-owned class and effort fields, a sync step, and drift refusal - too much overhead; a hand fix reaching one Harness silently would be costly to trace.
- rejected: refusing to install an agent with no pin - a shipped default plus a named notice keeps updates flowing.
- rejected: default notices at launch or in-session - costlier to build; Update Script output is enough.
- parked: per-machine default override - no proven need on either machine.
- parked: effort levels beyond `low`, `medium`, `high` - revisit if the common levels prove too coarse.
- deferred-to-spec: R48 - how a Copilot display name becomes Claude Code's model value, and a Claude entry Claude Code does not recognize.
- deferred-to-spec: R50 - default model and effort values, and notice wording.
