## Existing Solution
- Three stack walkthrough guides exist in `docs/` (`walkthrough-node.md`, `walkthrough-typescript.md`, and `walkthrough-csharp.md`), each covering setup, Language Add-on configuration, an end-to-end build, Day-2 usage, and a quick reference.
- Each guide currently features a different one-shot CLI example (`env-check`, `csv-stats`, `todo-cli`) and lists four practice CLI ideas (`env-check`, `csv-stats`, `todo-cli`, `slug-rename`).
- None of the walkthroughs feature an interactive REPL loop or walk through a concrete multi-feature Day-2 evolution.
- Touches: `docs/walkthrough-node.md`, `docs/walkthrough-typescript.md`, `docs/walkthrough-csharp.md`.

## Problem
- Using three different one-shot CLI examples makes comparing the workflow across stacks harder, and no walkthrough shows how to verify an interactive REPL session or evolve an existing app with new features.
- Desired outcome: all three walkthroughs feature one shared integer calculator REPL (`calc-repl`) end-to-end, including interactive-session verification and a concrete Day-2 evolution pass.

## Users
- `Developer` - follows a stack walkthrough to set up a new repository, practice the Workflow Core end-to-end, and learn how to evolve an existing app on Day 2.

## Workflow
- trigger: the Developer opens one of the three walkthroughs in `docs/` to practice the Workflow Core on a new repository.
- Part 1–3: the Developer sets up `calc-repl`, configures the stack's Language Add-ons, and runs brain-storm, behavior-spec, and `/pull-work` to build the v1 integer calculator REPL (`+`, `-`, `*`, `/` with standard operator precedence, truncating integer division, and clean exit).
- alternate path: divide-by-zero or an invalid expression in the REPL -> informs the user and prompts for another expression without crashing the loop.
- Part 3 verification: the walkthrough explains how to drive an interactive REPL session in automated black-box acceptance runs (piped `stdin` or spawned process I/O) and shows Step 4 PowerShell verification for all v1 paths.
- Part 4 Day-2 bug path: the Developer reports a `calc-repl` defect via `/pull-work calc-repl bug: <description>`.
- Part 4 Day-2 evolution path: the Developer runs one combined brain-storm -> behavior-spec -> `/pull-work` pass adding unary negative numbers, parentheses, and exponents (with negative exponents reporting an unsupported error without crashing), with a note that these features can also be split into separate passes.
- successful outcome: the Developer completes v1 and Day-2 evolution on `calc-repl` following any of the three walkthroughs without ambiguity.
