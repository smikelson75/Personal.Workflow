## Existing Solution
- Workflow Core lives in `.github/` (9 skills, 5 agents, one locked-tests hook, `tools/workflow-check/`) and is working.
- Distribution is manual copying into each repository's `.github/`; Language Add-ons exist for C#, Node JavaScript, and Node TypeScript only.
- The locked-tests guard is registered only in `.github/hooks/locked-tests.json`, which Claude Code never reads, in a deny format Claude Code ignores, so Claude Code is unguarded today.
- 9 skill files name `.github/...` paths relative to the launch folder (`pull-work` most), which break when Workflow Core is not inside the launched repository.

## Problem
- The Developer works in up to five Project Repos a day, one repository per stack (.NET C#, PowerShell, database schemas, more coming), switching Harnesses mid-project by tokens left and need.
- Per-repository copies drift to different versions, and the workflow was built for Copilot first, leaving Claude Code differences to reconcile.
- API changes often need changes in a separate database Project Repo; ordering mistakes caused past rework.
- Desired outcome: manage the workflow from one place, use it in every Project Repo without copying it in, load only the stack's Language Add-on, switch Harnesses seamlessly, and coordinate cross-repo changes.

## Users
- `Developer` - builds across many Project Repos on a personal machine and a restricted work machine; wants one workflow version everywhere with no manual upkeep.

## Workflow
- update: from a `Personal.Workflow` clone (personal) or downloaded zip (work), the Developer runs the Update Script against that machine's Home Repo.
- launch: in the Project Repo, the Developer runs the Launch Script with a Harness name.
- relay: the Developer launches the other Harness in the same Project Repo; `.workflow/` and commits carry state.
- fallback: no stack in `AGENTS.md`, or no add-on for it -> Workflow Core only, with a warning.
- manual path: direct Harness commands from `README.md` give the same session, minus warnings.
- coordination: cross-repo changes follow the Coordination Playbook.
- successful outcome: each Project Repo runs one visible workflow version in either Harness with only its stack's add-on.

## Constraints
- `Personal.Workflow` is only where the workflow is developed; each machine has one Home Repo attached to every session.
- Each Project Repo's own `AGENTS.md` states its stack and architecture; the Home Repo's `AGENTS.md` holds only Project Pointers.
- Copying Workflow Core into a repository stays supported as a backup path.
- Targets are Claude Code and Copilot CLI only; VS Code is an optional viewer.
- security/permission assumption: at work the only accepted update path is a downloaded zip plus the Update Script against a Home Repo the Developer names, with no network and touching only workflow-owned files; more needs agreement at work.
- security/permission assumption: Copilot CLI skips repository hooks in untrusted folders; the Gate's lock verification is the backstop, with no trust detection.
- imposed format: Harness hook payloads, deny formats, and skill and agent discovery locations - owner: Anthropic and GitHub.
- quality need: switching Harness mid-Card feels seamless; R35 lands first so Claude Code is guarded while v1 is built.
- accepted risk: two attached folders and the Claude Code settings option are unprobed on the work machine; `README.md` direct commands are the fallback.
